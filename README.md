# Crew Change Tracker

ระบบติดตามงานเปลี่ยนลูกเรือของ บริษัท ซัคเซส มารีน เซอร์วิส จำกัด ตามใบเสนอราคา QT-2569-0921-01
เดินตามกระบวนการ 9 ขั้นตอนของบริษัท · สำนักงานใช้บนคอมพิวเตอร์ · พนักงานภาคสนามใช้บนมือถือ · Owner ดูผ่านลิงก์

คู่มือผู้ใช้: [docs/manual.html](docs/manual.html) (PDF: `docs/คู่มือการใช้งาน-CrewChangeTracker.pdf`)

## โครงสร้าง

| ส่วน | ที่อยู่ | หน้าที่ |
|---|---|---|
| Worker (API) | `src/index.js` | เส้นทาง API ทั้งหมด งาน ลูกเรือ จุดเวลา รูป ลิงก์ Owner Excel สำรองข้อมูล |
| สิทธิ์และการเข้าระบบ | `src/auth.js` | รหัสผ่าน PBKDF2-SHA256 · session cookie HttpOnly 60 วัน · ล็อก 15 นาทีเมื่อผิด 8 ครั้ง |
| ค่าเริ่มต้น | `src/settings.js` | จุดสถานะ เอกสาร เรื่องที่ได้รับแต่งตั้ง เวลาถือว่าช้า จำนวนบัญชีสูงสุด 15 |
| Excel | `src/xlsx.js` | สร้างไฟล์ .xlsx โดยไม่ใช้ไลบรารีภายนอก |
| ฐานข้อมูล | `migrations/` | Cloudflare D1 (SQLite) |
| หน้าเว็บ | `public/` | HTML + JavaScript โมดูล ไม่มีขั้นตอน build · ติดตั้งเป็นไอคอนบนมือถือได้ (`manifest.webmanifest`, `sw.js`) |
| ตรรกะเวลา / อีเมล | `public/js/core.js` | สถานะช้า / ตามแผน การเลื่อนเวลาคาดการณ์ ร่างอีเมลทุกแบบ (เวลาไทย UTC+7 ทุกที่) |
| เอกสาร OK TO BOARD | `public/js/oktb.js` | วาดจดหมายบน canvas ขนาด A4 แล้วรวมกับสำเนาพาสปอร์ต Seaman book และตั๋วเครื่องบินเป็น PDF ไฟล์เดียวในเบราว์เซอร์ของพนักงานสำนักงาน (โหลดเมื่อกดสร้างเอกสารเท่านั้น) |

บริการที่ใช้: Cloudflare Workers (แผน Paid $5/เดือน) · D1 (ย้อนหลังด้วย Time Travel ได้ 30 วันบนแผน Paid, 7 วันบนแผนฟรี) · R2 (รูปถ่าย สำเนาเอกสารลูกเรือ รูปหัวจดหมาย/ลายเซ็น/ตราประทับ และไฟล์สำรอง)

### ไลบรารีภายนอก

ทั้งระบบใช้ไลบรารีภายนอกตัวเดียว เพราะตั๋วเครื่องบินมาเป็นไฟล์ PDF และต้องรวมเข้าเล่มเดียวกัน:

| ชื่อ | รุ่น | สัญญาอนุญาต | ไฟล์ |
|---|---|---|---|
| [pdf-lib](https://github.com/Hopding/pdf-lib) | 1.17.1 | MIT | `public/js/vendor/pdf-lib.esm.min.js` |

เป็นไฟล์ `dist/pdf-lib.esm.min.js` จากแพ็กเกจ npm `pdf-lib@1.17.1` คัดลอกมาทั้งไฟล์โดยไม่แก้ (SHA-256 `72c052d97b4d5d9fa6cdbdcb7ad709f03d4ddb1122390cb3afeba4d88651d969`) ไม่อยู่ใน `package.json` ไม่มีขั้นตอน build · โหลดด้วย `import()` ตอนกดสร้างเอกสารเท่านั้น ไม่อยู่ในรายการ precache ของ `sw.js` และทำงานได้ภายใต้ Content-Security-Policy `script-src 'self'` (ไม่ใช้ eval) · ถ้าจะอัปเดตรุ่น ให้ `npm pack pdf-lib@รุ่นใหม่` ในโฟลเดอร์ชั่วคราว แล้วคัดลอกไฟล์เดียวกันมาแทน แก้ตารางนี้ และรัน `npm run test:e2e:oktb`

### โครงสร้างไฟล์ใน R2 (bucket `cct-files`)

| โฟลเดอร์ | เก็บอะไร | ใครเปิดได้ผ่านระบบ |
|---|---|---|
| `photos/เลขงาน/เลขลูกเรือ/` | รูปที่พนักงานภาคสนามถ่าย | สำนักงาน และพนักงานที่ดูแลลูกเรือคนนั้น |
| `docs/เลขงาน/เลขลูกเรือ/` | สำเนาพาสปอร์ต Seaman book ตั๋วเครื่องบิน และไฟล์อื่นของลูกเรือ | สำนักงานเท่านั้น (`GET /api/files/:id`) |
| `brand/letterhead` `brand/signature` `brand/stamp` | หัวจดหมาย ลายเซ็น ตราประทับ ที่ผู้ดูแลระบบอัปโหลด | สำนักงานเท่านั้น (`GET /api/brand/:kind`) |

bucket ไม่เปิดสาธารณะ ทุกไฟล์ออกผ่าน Worker ที่ตรวจสิทธิ์ก่อนเสมอ · ลบลูกเรือหรือ "ลบงานนี้ถาวร" จะลบไฟล์ใน `photos/` และ `docs/` ของงานนั้นออกจาก R2 ด้วย

## รันบนเครื่อง

```bash
npm install
```

```bash
npx wrangler d1 migrations apply cct --local
```

สร้างไฟล์ `.dev.vars` (ไม่ขึ้น git) ใส่ `SETUP_KEY=รหัสติดตั้งสำหรับเครื่องนี้` แล้ว

```bash
npm run dev
```

เปิด http://127.0.0.1:8787 ครั้งแรกระบบพาไปหน้า "ติดตั้งระบบครั้งแรก" ให้สร้างบัญชีผู้ดูแลระบบด้วย SETUP_KEY

ข้อมูลทดสอบ (ใช้กับเครื่องตัวเองเท่านั้น สคริปต์ปฏิเสธถ้าไม่ใช่ localhost):

```bash
ADMIN_PASS=รหัสผู้ดูแล node scripts/seed-local.mjs
```

## ทดสอบ

```bash
npm test
```

รัน Worker จริงบนพอร์ต 8931 แล้วทดสอบ 27 ชุด: การติดตั้งครั้งแรก การกันคำขอข้ามเว็บ (CSRF) จำนวนบัญชีสูงสุด การล็อกบัญชี (บัญชีที่ล็อกตอบเหมือนชื่อผู้ใช้ที่ไม่มีอยู่) สิทธิ์แต่ละบทบาท 9 ขั้นตอน การยืนยันจุดตามลำดับและการส่งซ้ำตอนไม่มีสัญญาณ รูป (รวมรูปที่ส่งทีหลังได้เวลาที่ถ่ายจริง) ลิงก์ Owner ไม่มีข้อมูลส่วนตัว Excel การปิดงาน สำรองข้อมูลทุกคืนและรายเดือน การกู้ข้อมูลจากไฟล์สำรองลงฐานข้อมูลเปล่าแล้วเทียบว่าตรงกันทุกแถว (รวมไฟล์สำรองรุ่นก่อนที่ยังไม่มีตารางเอกสาร) และการเปลี่ยนรหัสผ่าน

ส่วนเอกสาร OK TO BOARD: วันหมดอายุพาสปอร์ต / Seaman book (ปฏิเสธวันที่ผิดรูปแบบ) การแนบไฟล์รูปและ PDF (ชนิดไฟล์ เนื้อไฟล์ต้องตรงชนิด ขนาดไม่เกิน 10 MB) พนักงานภาคสนาม หัวหน้างานภาคสนาม ลิงก์ Owner และคนที่ไม่ได้เข้าระบบ เปิด แนบ ลบไฟล์ไม่ได้และไม่ได้รับเลข Seaman book / วันหมดอายุ / รายการไฟล์ การลบไฟล์ ลบลูกเรือ ลบงาน งานที่ปิดแล้วแนบและลบไม่ได้ ตัวเลือกจดหมายที่บันทึกไว้กับงาน รูปหัวจดหมาย / ลายเซ็น / ตราประทับ (ผู้ดูแลระบบอัปโหลด สำนักงานอ่านได้) และการตรวจข้อความจดหมายในหน้าตั้งค่า

### ทดสอบหน้าจอแบบผู้ใช้จริง (e2e)

เปิด Chrome แบบไม่มีหน้าต่างแล้วกดใช้งานจริงตั้งแต่ขั้นตอน 1-9 มือถือพนักงานภาคสนาม (ยืนยันจุด บันทึก รูป ย้อนกลับ) หน้า Owner หลังบ้าน และปิด/เปิดงาน รวม 34 ข้อ ต้องติดตั้ง Google Chrome ในเครื่องก่อน (ถ้าไม่ได้อยู่ที่ `C:/Program Files/Google/Chrome/Application/chrome.exe` ให้ตั้ง `CHROME=ที่อยู่ไฟล์ chrome`) ใช้กับเครื่องตัวเองเท่านั้น สคริปต์ปฏิเสธถ้าไม่ใช่ localhost

1. หน้าต่างแรก: `npm run dev` (พอร์ต 8787 ฐานข้อมูลต้องว่าง)
2. สร้างผู้ดูแลระบบคนแรกด้วย SETUP_KEY ใน `.dev.vars` ใช้ชื่อผู้ใช้ `somying` (หรือชื่ออื่นแล้วตั้ง `ADMIN_USER` ให้ตรงกันทุกคำสั่ง) ผ่านหน้า "ติดตั้งระบบครั้งแรก" ที่ http://127.0.0.1:8787 ก็ได้
3. หน้าต่างที่สอง:

```bash
ADMIN_PASS=รหัสผู้ดูแล node scripts/seed-local.mjs
ADMIN_PASS=รหัสผู้ดูแล npm run test:e2e
```

ผลบรรทัดสุดท้ายต้องเป็น `PASS 34 / FAIL 0 / CONSOLE 0` (ถ้ามีข้อพังจะจบด้วย exit code 1) การทดสอบแก้ข้อมูลจริงในฐานข้อมูลบนเครื่อง จะรันซ้ำต้องเริ่มจากฐานข้อมูลว่างใหม่ (ลบ `.wrangler/state` แล้ว apply migrations ใหม่)

เอกสาร OK TO BOARD มีสคริปต์แยก ใช้ฐานข้อมูลที่ seed ใหม่เหมือนกัน (รันก่อนหรือแทน `test:e2e` ก็ได้ แต่อย่ารันซ้ำบนฐานข้อมูลเดิม):

```bash
ADMIN_PASS=รหัสผู้ดูแล npm run test:e2e:oktb
```

สคริปต์กรอกวันหมดอายุและเลข Seaman book ของลูกเรือ 2 คน แนบรูปพาสปอร์ตและตั๋ว PDF 2 หน้าที่สร้างขึ้นเองให้แต่ละคน อัปโหลดหัวจดหมาย ลายเซ็น ตราประทับตัวอย่างที่หน้าตั้งค่า แล้วกดสร้างเอกสารที่ขั้นตอนที่ 4 เก็บไฟล์ PDF ที่ดาวน์โหลดได้จริงมานับหน้า (มีหัวจดหมายและแนบสำเนา = 7 หน้า ไม่มีหัวจดหมายไม่แนบสำเนา = 1 หน้า) ตรวจว่าไม่มีอะไรล้นจอที่ความกว้าง 390 และไม่มีการละเมิด Content-Security-Policy ภาพหน้าจดหมายทั้งสองแบบและไฟล์ PDF อยู่ที่ `tests/e2e/out/` (ไม่ขึ้น git) ผลบรรทัดสุดท้ายต้องเป็น `FAIL 0 / CONSOLE 0` · รูปและไฟล์ที่ใช้ทดสอบสร้างจากโค้ดทั้งหมด (`tests/gen.mjs`) ไม่มีเอกสารจริงของใครใน repo

สคริปต์อื่น ใช้ข้อมูลจาก seed เหมือนกัน: `npm run test:e2e:audit` ตรวจทุกหน้าที่ความกว้าง 360-1440 ว่าไม่มีตัวหนังสือตกบรรทัด/ล้นจอ/ปุ่มเล็กเกินกด (ตั้ง `SHOTS=all` เพื่อเก็บภาพไว้ที่ `tests/e2e/out/`) และ `npm run test:e2e:offline` ตัดเน็ตแล้วกดยืนยันจุดบนมือถือ ต้องค้างในเครื่องแล้วส่งเองเมื่อเน็ตกลับมา ทุกสคริปต์รับ `BASE=http://127.0.0.1:พอร์ต` ถ้าไม่ได้ใช้พอร์ต 8787

## ติดตั้งขึ้นระบบจริง (ทำครั้งเดียว)

สมัคร Cloudflare ด้วยอีเมลกลางของบริษัท (บัญชีเป็นของบริษัท ผู้ให้บริการได้สิทธิ์ดูแลผ่าน Members) และเปิดแผน Workers Paid

ต้องเป็นแผน Workers Paid เท่านั้น: การเข้าระบบและการตั้งรหัสผ่านใช้ PBKDF2 100,000 รอบ ใช้ CPU เกินเพดาน 10 ms ต่อคำขอของแผนฟรี บนแผนฟรีจะเข้าระบบไม่ได้เลย (error 1102 Worker exceeded resource limits) ยืนยันแผนที่ Cloudflare หน้า Workers & Pages เมนู Plans ก่อนเริ่มทดสอบ และอย่าแก้ด้วยการลดจำนวนรอบ

1. เข้าระบบ: `npx wrangler login`
2. สร้างฐานข้อมูล: `npx wrangler d1 create cct` แล้วนำ `database_id` ที่ได้ไปแทนค่า `database_id` ใน `wrangler.jsonc` (บรรทัด 19) และแทนค่า `account_id` (บรรทัด 4) ด้วย Account ID ของบัญชีที่ใช้ ค่าที่อยู่ในไฟล์ตอนนี้เป็นของบัญชีบริษัทที่ขึ้นระบบแล้ว
3. สร้างที่เก็บไฟล์: `npx wrangler r2 bucket create cct-files`
4. สร้างตาราง: `npm run db:remote`
5. ตั้งรหัสติดตั้ง: `npx wrangler secret put SETUP_KEY` (ใช้ครั้งเดียวตอนสร้างผู้ดูแลคนแรก)
6. ขึ้นระบบ: `npm run deploy`
7. ผูกโดเมน เช่น `crew.ชื่อบริษัท.com` ที่ Cloudflare หน้า Workers & Pages เมนู Settings หัวข้อ Domains & Routes
8. เปิดเว็บ สร้างผู้ดูแลระบบคนแรก แล้วเพิ่มผู้ใช้ รถ โรงแรม ที่หน้า "ตั้งค่าระบบ"

### อัปเดตระบบที่ขึ้นใช้งานแล้ว

ทำตามลำดับนี้เสมอ ฐานข้อมูลก่อน โค้ดทีหลัง:

1. `npm run db:remote` ใช้ไฟล์ใน `migrations/` ที่ฐานข้อมูลจริงยังไม่เคยใช้ ตามลำดับเลข รุ่นเอกสาร OK TO BOARD เพิ่ม `migrations/0004_oktb.sql` (คอลัมน์วันหมดอายุพาสปอร์ต เลขและวันหมดอายุ Seaman book ของลูกเรือ ตัวเลือกจดหมายของงาน และตาราง `crew_files`) คำสั่งนี้เพิ่มคอลัมน์และตารางอย่างเดียว ไม่แตะข้อมูลเดิม และโค้ดรุ่นเก่ายังทำงานได้ระหว่างรอขั้นถัดไป
2. `npm run deploy`

ถ้าสลับลำดับ (ขึ้นโค้ดก่อนสร้างตาราง) หน้างานของสำนักงานจะเปิดไม่ได้จนกว่าจะรันข้อ 1 · หลังอัปเดต ให้ผู้ดูแลระบบอัปโหลดหัวจดหมาย ลายเซ็น ตราประทับ และกรอกชื่อผู้ประสานงาน / ผู้ลงนาม ที่ "ตั้งค่าระบบ" แท็บ "ตั้งค่าทั่วไป" การ์ด "เอกสาร OK TO BOARD" (รูปจริงของบริษัทอยู่ใน R2 เท่านั้น ห้ามใส่ใน repo)

## สำรองและกู้คืนข้อมูล

สำรอง 3 ชั้น ไม่ต้องมีคนกด:

| ชั้น | เก็บที่ | ความถี่ | ใช้ทำอะไร |
|---|---|---|---|
| ฐานข้อมูล D1 Time Travel | Cloudflare | ต่อเนื่อง ย้อนได้ 30 วัน (แผน Paid) / 7 วัน (แผนฟรี) | กู้ทั้งฐานข้อมูลไปจุดเวลาใดก็ได้ |
| `backups/daily/วันที่.json.gz` | R2 → NAS ของบริษัท | ทุกคืน 02:00 เก็บ 35 วัน | กู้ระบบทั้งหมดลงฐานข้อมูลใหม่ (ทดสอบใน `npm test` แล้ว) |
| `backups/ปี-เดือน.xlsx` | R2 → NAS ของบริษัท | ทุกวันที่ 1 | เปิดอ่านด้วย Excel ส่งบัญชี / เก็บเป็นหลักฐาน |

รูปถ่ายทั้งหมดอยู่ใน R2 โฟลเดอร์ `photos/` และถูกดึงไป NAS พร้อมกัน เช่นเดียวกับสำเนาเอกสารลูกเรือใน `docs/` และรูปหัวจดหมาย ลายเซ็น ตราประทับใน `brand/` เพราะงาน sync ดึงทั้ง bucket

ข้อควรรู้เรื่องสำเนาพาสปอร์ตบน NAS: งาน sync ตั้งให้ไม่ลบไฟล์ปลายทาง ดังนั้นเมื่อลบลูกเรือหรือลบงานในระบบ ไฟล์ใน R2 หายทันที แต่สำเนาที่ NAS ดึงไปแล้วยังอยู่ ต้องลบที่ NAS เองตามนโยบายเก็บข้อมูลของบริษัท · ถ้าบริษัทไม่ต้องการเก็บสำเนาพาสปอร์ตและลายเซ็นไว้ที่ NAS ให้ตั้งตัวกรองในงาน HBS3 ไม่รวมโฟลเดอร์ `docs/` และ `brand/` (ถ้าไม่รวม จะกู้ไฟล์สองโฟลเดอร์นี้จาก NAS ไม่ได้ ต้องแนบและอัปโหลดใหม่) · สิทธิ์เข้าโฟลเดอร์ปลายทางบน NAS ควรให้เฉพาะคนที่ดูเอกสารลูกเรือได้

### ตั้ง NAS ให้ดึงข้อมูลทุกคืน (QNAP TS-431KX ทำครั้งเดียว)

1. Cloudflare หน้า R2 เมนู Manage R2 API Tokens สร้าง token สิทธิ์ **Object Read only** เฉพาะ bucket `cct-files` จด Access Key ID, Secret Access Key และ Account ID
2. QNAP เปิดแอป **Hybrid Backup Sync 3** (ติดตั้งจาก App Center ถ้ายังไม่มี) เพิ่มปลายทางแบบ Cloud: **S3 Compatible**
   - Server / Endpoint: `ACCOUNT_ID.r2.cloudflarestorage.com` · ใช้ HTTPS · Region: `auto`
   - ใส่ Access Key ID และ Secret Access Key จากข้อ 1
3. สร้างงาน **Sync แบบ One-way** จาก bucket `cct-files` มาที่โฟลเดอร์ NAS เช่น `/Backup/CrewChange` ตั้งเวลา **ทุกวัน 03:00** (หลังระบบสร้างไฟล์ 02:00) ปิดตัวเลือกลบไฟล์ปลายทาง เพื่อให้ NAS เก็บของเก่าไว้เกิน 35 วันได้
4. กดรันครั้งแรก ตรวจว่ามีโฟลเดอร์ `backups/daily` และ `photos` บน NAS

token นี้อ่านได้อย่างเดียว ถ้า NAS ถูกเจาะก็แก้หรือลบข้อมูลในระบบไม่ได้ · NAS ไม่ต้องเปิดพอร์ตออกอินเทอร์เน็ต เพราะ NAS เป็นฝ่ายดึงออกไปเอง

### กู้คืน

กู้ฐานข้อมูลย้อนเวลา (ภายใน 30 วันบนแผน Paid หรือ 7 วันบนแผนฟรี):

```bash
npx wrangler d1 time-travel info cct
```

```bash
npx wrangler d1 time-travel restore cct --timestamp=2026-10-01T09:00:00+07:00
```

กู้จากไฟล์สำรองทุกคืน (เช่น ย้ายไปบัญชี Cloudflare ใหม่ หรือกู้จากไฟล์บน NAS) ถ้าย้ายบัญชี ให้ทำขั้นติดตั้ง 2–6 ในบัญชีใหม่ก่อน รวมถึงเปลี่ยน `account_id` และ `database_id` ใน `wrangler.jsonc` เป็นของบัญชีใหม่:

```bash
node scripts/backup-to-sql.mjs 2026-10-01.json.gz restore.sql
```

```bash
npx wrangler d1 execute cct --remote --file restore.sql
```

รูปถ่ายกู้ด้วยการอัปโหลดโฟลเดอร์ `photos/` จาก NAS กลับเข้า bucket `cct-files` ชื่อไฟล์เดิม (เช่นใช้ HBS3 sync ย้อนทาง หรือ `rclone copy`) สำเนาเอกสารลูกเรือ (`docs/`) และรูปหัวจดหมาย ลายเซ็น ตราประทับ (`brand/`) กู้วิธีเดียวกัน ไฟล์สำรองทุกคืนเก็บรายการไฟล์ (ตาราง `crew_files`) และบันทึกว่ามีรูปใดอัปโหลดไว้ แต่ไม่ได้เก็บตัวไฟล์ · ไฟล์สำรองที่สร้างก่อนรุ่นเอกสาร OK TO BOARD ยังกู้ได้ตามปกติ

## ความปลอดภัยและข้อมูลส่วนบุคคล

- repo นี้เป็น public: ห้ามใส่ข้อมูลลูกเรือจริง รหัสผ่าน โทเคน หรือไฟล์ `.dev.vars` ใน repo เด็ดขาด ค่าลับทั้งหมดตั้งด้วย `wrangler secret put` เท่านั้น
- ลิงก์ Owner แสดงเฉพาะชื่อ ตำแหน่ง เที่ยวบิน และเวลา ไม่มีเลขพาสปอร์ต หมายเหตุ รูป หรือข้อมูลพนักงาน
- พนักงานภาคสนามเห็นเฉพาะลูกเรือที่ได้รับมอบหมาย และไม่เห็นเลขบัตรของพนักงานคนอื่น
- สำเนาพาสปอร์ต Seaman book ตั๋วเครื่องบิน วันหมดอายุ เลข Seaman book ลายเซ็น และตราประทับ เปิดได้เฉพาะบัญชีสำนักงานและผู้ดูแลระบบ พนักงานภาคสนาม (รวมหัวหน้างานที่เห็นลูกเรือทุกคน) และลิงก์ Owner ไม่ได้รับข้อมูลเหล่านี้เลย ทั้งในข้อมูลที่ส่งให้หน้าจอและผ่านที่อยู่ไฟล์โดยตรง (ทดสอบใน `npm test`)
- ไฟล์ที่แนบส่งกลับด้วย `Cache-Control: no-store`, `X-Content-Type-Options: nosniff` และ `Content-Security-Policy: default-src 'none'` รับเฉพาะ JPG / PNG / WEBP / PDF ที่เนื้อไฟล์ตรงกับชนิด · เอกสาร OK TO BOARD ประกอบในเบราว์เซอร์ของพนักงานสำนักงาน ไม่มีการส่งเอกสารไปประมวลผลที่บริการอื่น
- ทุกคำขอที่แก้ข้อมูลต้องมาจากหน้าระบบเอง (ตรวจ Origin และ header `x-cct`) · หน้าเว็บใช้ Content-Security-Policy ใน `public/_headers`
